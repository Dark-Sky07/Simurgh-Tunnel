# مقایسهٔ سیمورغ با پروژه‌های هم‌خانواده

[English](COMPARISON.md) · **فارسی**

این صفحه یک مقایسهٔ صادقانه بین سیمورغ و ابزارهایی است که یک اپراتور ایرانی
برای همین کار (رله در ایران + خروج در خارج) استفاده می‌کند. اینجا می‌نویسیم
سیمورغ **چه چیزی بهتر دارد**، **چه چیزی کم دارد** و هر کاستی تقریباً چقدر
هزینه دارد.

هر چیزی که با *(اینجا بررسی شد)* علامت خورده، در سورس همین مخزن خوانده شده یا
در همین چک‌اوت اجرا شده است (۱۴۰۵/۰۷/۲۴) — نه کپی از README دیگران.

## جاهایی که سیمورغ جلوتر است

اینها چیزهای کوچکی نیستند — دلیل وجود پروژه همین‌هاست:

* **واقعاً شبیه یک وب‌سایت است.** دست‌دادن TLS واقعی، گواهی واقعی، صفحهٔ طعمهٔ
  nginx (یا `fallback = "site:host:port"` که واقعاً همان سایت را سرو می‌کند) و
  `split = n` که باعث می‌شود اولین سگمنت TCP روی سیم فقط چند بایت باشد
  *(اینجا بررسی شد: `carriers.py`، `decoy.py`، `tlsio.py` و تست‌های `split`)*.
  rathole، frp، gost و wstunnel به کاوشگر خطای handshake، reset یا «این یک تونل
  است» تحویل می‌دهند (تنها استتار قابل‌مقایسه در این لیست `--backend` در chisel
  است که آن هم خام‌تر است). کاریز ws/wss به‌شکل CDN و پکت‌های quic مهروموم‌شده
  دارد، ولی سایت طعمه ندارد.
* **احراز هویت بدون اثری برای شناسایی.** هدر ۲۵ بایتی، HMAC-SHA256[:16]، پنجرهٔ
  ±۱۸۰ ثانیه، کش replay ۳۰۰ ثانیه *(اینجا بررسی شد: `protocol.py`)*؛ توکن غلط →
  صفحهٔ طعمه.
* **تنظیم خودکار پنجره (BDP).** پنجرهٔ هر استریم زیر بار رشد می‌کند و یک
  بودجهٔ اعتباری مشترک برای هر اتصال تونل وجود دارد *(اینجا بررسی شد:
  `mux.py`)* — همین چیزی است که ۲MB/s را روی مسیر ۶۰ms به ۴۰MB/s می‌رساند و
  بزرگ‌ترین تفاوت با rathole/frp است که پنجرهٔ ثابت دارند.
* **دو موتور، یک پروتکل، نصب بدون اینترنتِ آزاد.** پایتون ۳٫۹+ با خوانندهٔ TOML
  باندل‌شده و بدون نیاز به PyPI، و موتور Go با همهٔ وابستگی‌ها وندرشده در
  `go/third_party/` *(اینجا بررسی شد: `tools/build-go.sh` با `GOPROXY=off`
  بیلد می‌کند)*. روی سروری که pip یا پروکسی Go بسته است، تفاوت «نصب می‌شود» و
  «نصب نمی‌شود» همین است.
* **ادعاهای آزموده‌شده، نه حرف.** ۱۷۱ تست در همین چک‌اوت سبز است
  *(اینجا اجرا شد: `python3 -m pytest -q` → ۱۵۳ passed در ۱۳۸ ثانیه روی پایتون
  ۳٫۱۱؛ README عدد ۱۲۶ را می‌گفت که هنگام نوشتن همین صفحه اصلاح شد)*، به‌علاوهٔ
  تست‌های Go و ماتریس زندهٔ حامل‌ها.
* **راحتی اپراتور:** یک دستور که خودش نقش سرور را تشخیص می‌دهد، لینک راه‌اندازی
  و `simurgh join`، منوی متنی، `simurgh doctor`، پنل دوزبانه، تغییر زندهٔ
  مپینگ‌ها بدون ری‌استارت، تعویض موتور بدون دست‌زدن به کانفیگ.

## چیزهایی که کم است (اولویت‌بندی‌شده)

تخمین زحمت برای کسی که این کد را می‌شناسد: **کم** = چند ساعت، **متوسط** = چند
روز، **زیاد** = یک هفته یا بیشتر.

### P0 — هستهٔ کار را لمس می‌کند

| کاستی | چه کسی دارد | چرا اینجا مهم است | زحمت |
|---|---|---|---|
| **حامل UDP-native (QUIC یا سبک KCP، یا «raw روی UDP» با ARQ+FEC)** | کاریز (`quic`, `kcp`)، frp (`kcp`, `quic`)، gost، wstunnel (WebTransport) | امروز UDP روی همان مالتی‌پلکسر TCP می‌رود و `simurgh/udp.py` خودش صادقانه می‌نویسد: «تونل کردن UDP روی تونل TCP باعث head-of-line blocking می‌شود، پس پروتکل‌های حساس به تأخیر (QUIC، WireGuard) آن را دوست ندارند» *(اینجا بررسی شد)*. WireGuard، Hysteria2، TUIC و اینباندهای QUIC سهم بزرگی از ترافیک ایران را دارند. این تنها کاستی‌ای است که رقیب می‌تواند با آن بگوید محصولش بهتر است. | **زیاد** برای QUIC (وندِر کردن یک استک QUIC قول «بیلد بدون شبکه» را می‌شکند، مگر مثل `third_party/xcrypto` وندر شود)؛ **متوسط** برای یک حامل UDP دست‌ساز با FEC روی همان رمزنگاری `raw` و فریمینگ `protocol.py` |
| **محدودهٔ پورت و افزودن گروهی mapping** | کاریز (`443,8080-8090`)، frp (port range) | هر ستاپ واقعی ۵ تا ۵۰ پورت فوروارد می‌کند (`443, 2053, 2083, 2087, 2096, 8443, 1000-1100`). `simurgh mapping add` هر بار فقط یک پورت می‌گیرد *(اینجا بررسی شد: `cli.py`، اعتبارسنجی تک‌پورت)*. | **کم** |
| **اتصال به خروج از طریق پروکسی بالادست (SOCKS5 / HTTP)** | rathole (`transport.tcp.proxy`)، wstunnel (`-p`)، frp (`transport.proxyURL`) | اجازه می‌دهد تونل از مسیر پروکسی/VPN/رولینگ لوکالِ موجود بیرون برود و وقتی سرور خارج پشت NAT است یا ارائه‌دهنده فقط پروکسی خروجی می‌دهد، راه‌حل است. پایهٔ زنجیره‌های «تونل روی تونل» که در ایران زیاد استفاده می‌شود. | **کم تا متوسط** |
| **چند خروج واقعی: تخصیص هر mapping به یک exit + توزیع بار + health check مقصد** | frp (proxy group + `healthCheck`)، gost (selector)، قالب‌های Azumi67 | `[[pool]]` فقط **failover** است — `_pick()` اولین endpoint سالم را برمی‌گرداند، پس همهٔ مپینگ‌ها روی همان سرور خارج اول می‌روند و بقیه تا زمان مرگ آن بی‌کار می‌مانند *(اینجا بررسی شد: `relay.py`)*. اپراتوری که ۳ سرور خارج دارد می‌خواهد پنل A روی خروج A باشد، پنل B روی خروج B، یا بار تقسیم شود، و می‌خواهد مقصد مرده تشخیص داده شود نه اینکه استریم refuse بخورد. | **متوسط** |
| **محدودیت سرعت و سهمیهٔ ترافیک per-mapping یا per-token** | frp (`bandwidthLimit`)، gost (limiter) | لازم برای فروش/شریک‌شدن یک پهنای باند بدون اینکه یک مشتری همه را بخورد، و برای سقف‌گذاری روی تونل اشتراکی. سیستم اعتبار سیمورغ **انصاف بین استریم‌ها** می‌دهد، نه **سقف برای هر پورت** *(اینجا بررسی شد: `mux.py` و `stats.py` که فقط شمارنده دارد)*. | **متوسط** |

## چیزهایی که عمداً کاستی نیستند

* **یک پروتکل تونل به‌جای شش حامل** یک *مزیت* است نه نقص: مسیرهای کد کمتر، دلیل
  آن است که سیمورغ می‌تواند رفتار یکسان روی همهٔ حامل‌ها و تعامل Go ⇄ Python را
  تضمین و تست کند. چیز گم‌شده **یک گزینهٔ UDP** است، نه پنج حامل جدید.
* **نبودن SOCKS5 در تونل** وعدهٔ «مشتری فقط آدرس را عوض می‌کند» را صادق نگه
  می‌دارد.
* **نبودن فریم‌ورک پلاگین**: یک webhook روی رخدادها ۹۰٪ ارزش را با ۵٪ هزینهٔ
  نگهداری می‌دهد.

### هنوز باز

P1 باقی‌مانده: بسته‌بندی (Docker/DEB/RPM)، یک `simurgh speedtest` کامل‌تر
(تأخیر زیر بار، افت UDP) و پروفایل‌های تنظیم
(`simurgh tune gaming|balanced|speed`).  سطح اپراتوری دیگر روی سمت پایتون
کامل است و **با** موتور Go هم کار می‌کند (موتور به‌عنوان فرزند تحت نظارت:
پنل، `/metrics`، هشدارها و ری‌استارت خودکار).

P2: لیسنر SOCKS5، TUN/TAP، اشتراک vhost، گیت‌وی SSH، پلاگین‌ها، پنل
چندسروره، IPv6 درجه‌یک، تنظیم‌های سوکت و سرویس ویندوز/مک.  در سمت Go هم
سیاست per-token در مسیر داده (لیست پورت/مقصد، سطل و کوتای هر توکن) و
عبور از پروکسی به‌صورت بومی باقی مانده؛ بقیهٔ کانفیگ را هر دو موتور یکسان
می‌خوانند (از جمله `cert_file`/`key_file` هر لیسنر).

## اگر فقط سه کار انجام شود

1. **یک حامل UDP-native** (P0) — تنها جایی که رقیب می‌تواند به‌درستی بگوید
   محصولش بهتر است.
2. **محدودهٔ پورت + افزودن گروهی + `simurgh update` + بکاپ** (P0/P1، همه کوچک) —
   درد روزمرهٔ اپراتور، چند ساعت کار.
3. **`/metrics` + API توکن‌دار + محدودیت per-mapping** (P1/P0) — پنل را از یک
   نمایشگر به چیزی تبدیل می‌کند که کسب‌وکار می‌تواند رویش صورت‌حساب بگذارد.
