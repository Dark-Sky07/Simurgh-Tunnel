# مرجع تنظیمات

[English](CONFIGURATION.md) · **فارسی**

<div dir="rtl">

سیمرغ همه‌چیز را در دو فایل TOML نگه می‌دارد. هر دو متن ساده‌اند، به‌صورت اتمیک
نوشته می‌شوند و مجوز `0600` دارند.

| سرور | فایل |
|---|---|
| خارج (اگزیت) | `/etc/simurgh/exit.toml` |
| ایران (رله) | `/etc/simurgh/relay.toml` |
| نصب کاربر عادی | `~/.simurgh/…` (با `--home` یا `SIMURGH_HOME` قابل تغییر) |
| رمز پنل | `/etc/simurgh/state.json` |
| گواهی‌ها | `/etc/simurgh/cert/{cert,key}.pem` |

تغییرات را با `simurgh restart` اعمال کنید. پورت‌ها را می‌توان بدون ری‌استارت هم
عوض کرد: از پنل یا با `simurgh mapping …`.

## `exit.toml` — سرور خارج

```toml
token = "kQ0…"                  # کلید مشترک، در دو سرور یکسان
name = "omega-de"               # نامی که در رله و پنل دیده می‌شود
cert_auto = true                # ساخت گواهی خودامضا در صورت نیاز
# cert_file = "/etc/letsencrypt/live/panel.example.com/fullchain.pem"
# key_file  = "/etc/letsencrypt/live/panel.example.com/privkey.pem"
allow_ips = []                  # لیست مجاز همتایان تونل (اختیاری)
push_ports = [443, 2053, 2083]  # پورت‌هایی که به رله پیشنهاد می‌شود
push_enabled = true
strict_ports = false            # true = فقط پورت‌های push_ports قابل اتصال‌اند
speedtest_port = 8808           # اندپوینت تست سرعت، فقط روی 127.0.0.1 (0 = خاموش)
proxy_protocol = "off"          # off | v1 | v2 — انتقال IP واقعی کاربر به پنل
log_level = "info"              # debug | info | warning | error

[[listen]]                      # برای هر اندپوینت تونل یک بلوک
carrier = "tls"                 # tls | wss | raw | plain
host = "0.0.0.0"
port = 443
path = "/ws"                    # مسیر HTTP برای wss (و tls)
fallback = "decoy"              # decoy | close — رفتار با غریبه‌ها
padding = true                  # استتار طول فریم‌ها
enabled = true
```

### حالت معکوس روی اگزیت

به‌جای گوش‌دادن، اگزیت به رله وصل می‌شود:

```toml
token = "kQ0…"
name = "omega-de"

[[listen]]
carrier = "tls"
port = 8443                     # پورتی که *رله* روی آن گوش می‌دهد
dial = "203.0.113.9"            # آدرس رله — همین خط حالت معکوس را فعال می‌کند
fingerprint = "AB:CD:…"         # پین گواهی رله (توصیه‌شده)
# insecure_skip_verify = true   # فقط برای تست
split = 3                       # ضد DPI: n بایت اول تنها برود
enabled = true
```

اگزیت خودش با عقب‌نشینی ۰.۵ تا ۱۵ ثانیه دوباره وصل می‌شود؛ ری‌استارت هیچ‌کدام از
دو طرف کار دستی لازم ندارد.

### کلیدهای مهم `exit.toml`

| کلید | پیش‌فرض | معنی |
|---|---|---|
| `token` | — | اجباری؛ کلید HMAC تونل |
| `name` | نام میزبان | نمایش در سمت رله |
| `cert_auto` | `true` | ساخت `/etc/simurgh/cert/*.pem` وقتی گواهی داده نشده |
| `allow_ips` | `[]` | اگر پر باشد، فقط این همتایان می‌توانند تونل باز کنند |
| `push_ports` | پورت‌های رایج پنل | پیشنهاد پورت‌ها به رله |
| `strict_ports` | `false` | رد کردن پورت‌هایی که به رله پیشنهاد نشده‌اند |
| `speedtest_port` | `8808` | اندپوینت سرعت، فقط روی `127.0.0.1` |
| `proxy_protocol` | `off` | ارسال هدر PROXY protocol به سرویس محلی |
| `log_level` | `info` | سطح لاگ |

### کلیدهای `[[listen]]`

| کلید | پیش‌فرض | معنی |
|---|---|---|
| `carrier` | `tls` | نوع استتار این اندپوینت: `tls`، `wss`، `raw` یا `plain` — هر دو موتور هر چهار حامل را دارند و می‌توانند مقابل هم قرار بگیرند |
| `host` / `port` | `0.0.0.0` / `8443` | آدرس گوش‌دادن (حالت مستقیم) |
| `path` | `/ws` | مسیر HTTP برای `wss` |
| `fallback` | `decoy` | `decoy` = سایت طعمه، `close` = قطع بی‌صدا |
| `decoy_file` | — | فایل HTML دلخواه برای طعمه |
| `padding` | `true` | پد کردن فریم‌ها تا اندازه‌ها معنا نداشته باشند. فقط حامل `raw` از آن استفاده می‌کند و فقط برای جهتی که خودش می‌فرستد: فریم پد‌شده روی اولین اندازه از ۱۲۸/۲۵۶/۵۱۲/…/۱۶۳۸۴ بایت که جا شود (یا مضرب بعدی ۶۴ بالاتر از آن) به‌علاوهٔ یک دنبالهٔ ۲ بایتی می‌نشیند، دقیقاً مثل `simurgh/carriers.py`. خاموش کردنش در یک طرف بی‌خطر است — طرف دیگر همچنان پد خودش را برمی‌دارد. |
| `split` | `0` (فایل‌هایی که `simurgh init` می‌نویسد: `3`) | چند بایت از **اولین نوشتن** در یک سگمنت TCP جدا بروند؛ بقیه حدود ۱۰ میلی‌ثانیه بعد می‌رسد، پس دستگاهی که فقط سگمنت اول یک اتصال را می‌خواند یک قطعهٔ ناقص می‌بیند. فقط دست‌دادن TLS تکه می‌شود، و فقط در طرفی که خودش dial می‌زند: در حالت مستقیم رله، در حالت معکوس اگزیت. `0` خاموشش می‌کند؛ `3` اندازهٔ هدر رکورد TLS است، پس قطعهٔ اول با همان دو بایتی شروع می‌شود که یک بازرس TLS-آشنا دنبالش است. هزینهٔ این کار یک مکث ۱۰ میلی‌ثانیه‌ای در هر اتصال تونل است، همان لحظهٔ برپایی. |
| `enabled` | `true` | خاموش کردن بدون حذف بلوک |
| `dial` | — | **حالت معکوس**: وصل شدن به این آدرس به‌جای گوش‌دادن |
| `fingerprint` | — | اثرانگشت SHA-256 گواهی رله (معکوس) |
| `insecure_skip_verify` | `false` | پذیرش هر گواهی (فقط تست) |
| `cert_file` / `key_file` | — | فقط برای `tls`/`wss`: گواهی **مخصوص همین لیسنر** که گواهی بالای فایل را بازنویسی می‌کند — یک سرور، چند دامنه، هر کدام گواهی خودش. هر دو موتور این کلید را می‌خوانند و اگزیت مثل بقیهٔ گواهی‌ها انقضایش را رصد می‌کند |

## `relay.toml` — سرور ایران

```toml
token = "kQ0…"
name = "ir-tehran"
dial = "relay"                  # relay = مستقیم، exit = معکوس
panel_port = 8787
accept_push = true              # پذیرش لیست پورت‌هایی که اگزیت پیشنهاد می‌دهد
keepalive = 25                  # فاصلهٔ پینگ (ثانیه)
stream_window = 262144          # پنجرهٔ شروعِ هر استریم (بایت)
max_stream_window = 16777216    # سقف رشد خودکار پنجره
chunk = 65536                   # حداکثر بار هر فریم
connections = 1                 # چند اتصال تونل باز بماند (۲ تا ۱۶ = استخر)
log_level = "info"

[exit]                          # سرور خارجی که به آن وصل می‌شویم (حالت مستقیم)
carrier = "tls"
address = "203.0.113.9"
port = 443
domain = "panel.example.com"    # SNI (اختیاری)
path = "/ws"
fingerprint = "AB:CD:…"         # پین گواهی (اختیاری)
insecure_skip_verify = false
split = 3                       # ضد DPI: n بایت اول تنها برود

[[pool]]                        # سرورهای خارجی جایگزین برای فِیل‌اُور
address = "198.51.100.7"
port = 443
carrier = "tls"

[[mapping]]                     # فوروارد پورت: ایران -> خارج
name = "panel"
listen = 443                    # پورت روی همین سرور (ایران)
target_host = "127.0.0.1"       # اگزیت به این آدرس وصل می‌شود
target_port = 443
udp = false
enabled = true
```

### حالت معکوس روی رله

```toml
token = "kQ0…"
name = "ir-tehran"
dial = "exit"                   # منتظر اتصال سرور خارج می‌مانیم
panel_port = 8787

[tunnel]                        # شنونده‌ای که اگزیت به آن وصل می‌شود
carrier = "tls"
host = "0.0.0.0"
port = 8443                     # این پورت را در فایروال باز کنید
path = "/ws"
fallback = "decoy"
cert_auto = true                # گواهی برای همین شنونده
```

در حالت معکوس بلوک `[exit]` وجود ندارد؛ رله هیچ‌جا وصل نمی‌شود. بلوک‌های
`[[mapping]]` دقیقاً مثل قبل می‌مانند، چون پورت‌های کاربران همیشه روی سرور ایران
هستند.

### کلیدهای مهم `relay.toml`

| کلید | پیش‌فرض | معنی |
|---|---|---|
| `token` | — | اجباری؛ باید برابر توکن اگزیت باشد |
| `dial` | `relay` | `relay` = مستقیم، `exit` = معکوس |
| `panel_port` | `8787` | پورت پنل وب |
| `accept_push` | `true` | اعمال لیست پورتی که اگزیت می‌فرستد |
| `keepalive` | `25` | فاصلهٔ پینگ |
| `stream_window` | `262144` | پنجرهٔ شروع هر استریم |
| `max_stream_window` | `16777216` | سقف رشد خودکار پنجره (۱۶ مگابایت) |
| `chunk` | `65536` | حداکثر بار فریم |
| `connections` | `1` | تعداد اتصال‌های تونل؛ ۲ تا ۱۶ بار ترافیک را پخش می‌کند |
| `speedtest_port` | `0` | اندپوینت محلی تست سرعت (`0` = خاموش)؛ رله آن را از دست‌دادن اولیهٔ اگزیت یاد می‌گیرد، پس `simurgh speedtest` تغییرش را دنبال می‌کند |
| `[exit]` | — | اندپوینت خارج (حالت مستقیم)؛ `split` را هم می‌پذیرد |
| `split` | در فایل‌های ساخت `simurgh init`: `3` | در `[exit]` (و در هر ورودی `[[pool]]`): چند بایت از اولین نوشتن در یک سگمنت TCP جدا بروند — همان ترفند ضد DPI که زیر `[[listen]]` توضیح داده شد. با `simurgh install --split N` (یا `init`) تنظیم می‌شود |
| `[tunnel]` | — | شنوندهٔ حالت معکوس |
| `[[pool]]` | `[]` | سرورهای خارجی جایگزین |
| `[[mapping]]` | `[]` | فوروارد پورت‌ها |

### کلیدهای سرعت و پایداری (هر دو فایل)

این سه کلید هم در `relay.toml` و هم در `exit.toml` وجود دارند؛ هر کدام
کوچک‌تر باشد همان اعمال می‌شود، پس تنظیم روی رله کافی است.

| کلید | پیش‌فرض | کار |
|---|---|---|
| `stream_window` | `۲۵۶ کیلوبایت` (موتور Go: `۱ مگابایت`) | مقدار در پروازی که استریم *پیش از* شناخت مسیر دارد. موتور Python از ۲۵۶ کیلوبایت خوب رشد می‌کند، ولی موتور کامپایل‌شده به شروع بزرگ‌تر نیاز دارد چون قاعدهٔ رشدش بر پایهٔ نرخ است و پنجرهٔ کوچک روی مسیر سریع هرگز رشد نمی‌کند. `simurgh init` خودش مقدار مناسب هر موتور را می‌نویسد. |
| `max_stream_window` | `۸ مگابایت` | سقف رشد خودکار. تانل سرعت واقعی هر استریم را می‌سنجد و تا وقتی استریم مسیر را اشباع کند پنجره را دو برابر می‌کند؛ پس یک کاربر روی مسیر طولانی ایران ⇄ اروپا دیگر به `window / RTT` محدود نمی‌شود. مصرف رم با تقاضا بالا و پایین می‌رود (فقط استریمی که واقعاً سریع می‌رود بزرگ می‌شود) و این عدد بدترین حالت برای هر کاربر پرمصرف است؛ روی VPS کوچک با صدها کاربر سنگین `۴ مگابایت` بگذارید و برای یک فلوی خیلی پرحجم `۱۶ مگابایت` یا بیشتر. |
| — (مشترک) | کف `۱۶ مگابایت`، سقف `۶۴ مگابایت` | بودجهٔ کردیت کلِ *یک اتصال* تونل: این بودجه از مجموع پنجرهٔ فعلی استریم‌های زنده پیروی می‌کند، پس ده‌ها کاربر روی یک اتصال یکدیگر را گرسنه نمی‌کنند و در همان حال طرفی که خواندن را متوقف کند نمی‌تواند بیشتر از سقف، حافظه اشغال کند. چیزی برای تنظیم ندارد؛ همین است که نمی‌گذارد ۱۰۰۰ کاربر روی یک ماشین به پنجرهٔ یک کاربر محدود شوند. |
| `connections` | `1` | تعداد اتصال‌های تونل از رله به اگزیت (۱ تا ۱۶). هر اتصال یک فلوی TCP و ظرفیت یک هسته است: روی مسیرهای طولانی و پرافت‌وخیز ۲ تا ۴ اتصال سرعت کل را خیلی بالا می‌برد و اگر یکی قطع شود فقط بخشی از کاربران لطمه می‌بینند. رله هر کاربر را به کم‌بارترین تونل می‌فرستد. |
| `chunk` | `۶۴ کیلوبایت` | بزرگ‌ترین بار هر فریم. فریم بزرگ‌تر یعنی سرباز کمتر به ازای هر بایت؛ ۶۴ کیلوبایت نقطهٔ تعادل خوبی است. |
| `engine` | `go` | موتور داده‌ای که این فایل را اجرا می‌کند: `go` (کامپایل‌شده، چند هسته‌ای، مصرف CPU بسیار کمتر به ازای هر گیگابایت) یا `python` (همه‌جا کار می‌کند). `simurgh init` وقتی این ماشین باینری را داشته باشد `go` می‌نویسد و وقتی نداشته باشد `python`، پس پیش‌فرض همان چیزی است که واقعاً نصب است. هر دو یک پروتکل دارند، پس یک طرف می‌تواند Go باشد و طرف دیگر Python. بعد از ساخت موتور Go (`sudo bash tools/build-go.sh`) با `simurgh engine go` سوئیچ کنید. پنل، منو و CLI همان Python می‌مانند. با `engine = "go"` موتور کامپایل‌شده به‌عنوان **فرزندِ تحت نظارت** پروسهٔ Python اجرا می‌شود: پنل، `/metrics` و هشدارها کنارش زنده می‌مانند (خود موتور Go هیچ پورت HTTP باز نمی‌کند)، فایل `state.json` رصد می‌شود تا بالا/پایین شدن تونل و رسیدن به کوتا اطلاع داده شود، و اگر موتور بمیرد با تأخیر پله‌ای (۰٫۵ تا ۳۰ ثانیه) دوباره بالا می‌آید و خبرش به اپراتور می‌رسد. با `simurgh relay --exec` پروسه را کامل به موتور Go می‌سپارید — سربار کمتر، ولی بدون پنل و بدون هشدار. |

اندازه‌گیری روی مسیر شبیه‌سازی‌شدهٔ ۶۰ میلی‌ثانیه‌ای (کانتینر ۲ هسته‌ای)،
یک کاربر، کریِر plain، انتقال ۸۰ مگابایتی: **۲ مگابایت بر ثانیه با پنجرهٔ
ثابت ۲۵۶ کیلوبایتی ← ۴۰.۴ مگابایت بر ثانیه با پنجرهٔ خودکار** (۲۰ برابر)،
و روی مسیر کوتاه ۲۳۳ مگابایت بر ثانیه (سقف یک هسته). با `connections = 4`
و سقف ۴ مگابایت بر ثانیه برای هر جریان، هشت کاربر به ۱۳.۰ مگابایت بر ثانیه
می‌رسند در برابر ۳.۶ مگابایت بر ثانیه روی یک تونل. مصرف رم محدود می‌ماند:
پنجرهٔ استریم بی‌کار تا `stream_window` برمی‌گردد، بودجهٔ مشترک هر اتصال را
کران‌دار می‌کند و کل فرایند بنچمارک (رله + اگزیت + مقصد) اوجی ۹۵ مگابایتی
داشت.

موتور Go همین سقف‌ها را بالاتر می‌برد و به ازای هر گیگابایت خیلی کمتر CPU
می‌خورد: `tools/build-go.sh` ← `simurgh engine go` ← ری‌استارت. اندازه‌گیری با
همان هارنس روی همان ماشین:

| بار کاری | موتور Python | موتور Go |
|---|---|---|
| یک استریم، مسیر ۶۰ms، ۸۰MB | ۴۰.۴ مگابایت بر ثانیه | **۴۲.۳ مگابایت بر ثانیه** (۳۳۸ مگابیت) |
| یک استریم، مسیر ۶۰ms، `tls` | ۲۲.۷ | **۳۰.۵** (۲۴۴ مگابیت) |
| یک استریم، مسیر کوتاه، ۲۵۶MB | ۲۳۳ | **۳۸۳** (۳.۰۷ گیگابیت) |
| ۶۴ کاربر روی **یک** اتصال تونل، ۲۰ms | — | **۴۳۰ مگابایت بر ثانیه** (۳.۴ گیگابیت) |
| ۶۴ کاربر روی دو اتصال تونل | — | **۵۰۳ مگابایت بر ثانیه** (۴.۰ گیگابیت) |
| هشت کاربر، ۴ تونل، سقف ۴MB/s | ۱۳.۰ | ۱۳.۰ |
| CPU برای هر ۲۵۶ مگابایت | ۰.۸۵ ثانیه‌هسته | **۰.۶ تا ۰.۸** |

هر ردیف یک پروسه است که رله + اگزیت + مسیر شبیه‌سازی‌شده + کلاینت آزمون را
با هم اجرا می‌کند، روی کانتینر ۲ هسته‌ای؛ پس اعداد محافظه‌کارانه‌اند (سرور
واقعی دو ماشین جدا دارد) و مسیر لوپ‌بک خوش‌بینانه است (بدون افت بسته).

برای هزار کاربر هم‌زمان قاعدهٔ کار این است: روی هر اتصال تونل چند ده استریم
*پرمصرف* نگه دارید و `connections` را بالا ببرید، چون هر اتصال یک هسته و یک
فلوی TCP جداگانه است:

```bash
simurgh init --exit-host 203.0.113.9 --connections 8   # ۱۰۰۰ کاربر، ۸ هسته
```

### کلیدهای `[[mapping]]`

| کلید | پیش‌فرض | معنی |
|---|---|---|
| `listen` | — | پورت باز‌شده روی سرور ایران |
| `listen_host` | `0.0.0.0` | آدرس اتصال آن پورت |
| `target_host` | `127.0.0.1` | آدرسی که **از سمت اگزیت** استفاده می‌شود |
| `target_port` | — | پورت سرویس روی سرور خارج |
| `udp` | `false` | فوروارد UDP به‌جای TCP. هر دیتاگرام یک فریم است، پس مرزها حفظ می‌شود و چیزی دوباره فرستاده نمی‌شود؛ وقتی طرف مقابل عقب بیفتد، دیتاگرام مثل یک سوکت UDP پر دور ریخته می‌شود. روی رله هر آدرس کلاینت استریم خودش را دارد و بعد از ۶۰ ثانیه سکوت جمع می‌شود، و اگزیت با هر استریم از یک سوکت UDP مستقل به مقصد حرف می‌زند. هر دو موتور آن را پشتیبانی می‌کنند. |
| `name` | — | برچسب در پنل و CLI |
| `enabled` | `true` | نگه‌داشتن رکورد ولی توقف فوروارد |

معادل‌های CLI:

```bash
simurgh mapping add 443 443 --name panel
simurgh mapping add 2096 2096 --udp
simurgh mapping add 8443 8443 --target-host 10.0.0.5
simurgh mapping toggle 443
simurgh mapping remove 443
```

## تست سرعت

```bash
simurgh speedtest                 # توان عبوری + تأخیر، هر دو طرف واقعی
simurgh speedtest --udp           # ... و افت/لرزش دیتاگرام‌ها
simurgh speedtest --streams 4     # چهار استریم تونل، جمع‌زده‌شده
simurgh speedtest --seconds 10 --json
simurgh speedtest --no-latency    # فقط توان عبوری (رفتار قبلی)
```

روی سمت **ایران** اجرا می‌شود و مستقیم از داخل تونل اندازه می‌گیرد — شامل
حامل، مالتی‌پلکسر و کنترل جریان؛ که همین نکتهٔ اصلی است:

| چه چیزی | چطور |
|---|---|
| دانلود / آپلود | اندپوینت فقط-لوکال اگزیت روی `speedtest_port` داده می‌دهد و هر چه بگیرد می‌بلعد |
| تأخیر، بی‌بار و زیر بار | استریم دوم در حالت *echo* باز می‌شود (اولین بایت‌هایش یک نشانهٔ جادویی است) و نمونه‌های کوچک رفت‌وبرگشتی زمان‌گیری می‌شوند: یک‌بار قبل از بار، بعد پشت‌سرهم وقتی لینک اشباع است |
| نمرهٔ bufferbloat | از رشد میانهٔ پینگ زیر بار: `A` ≤۳۰ms، `B` ≤۶۰، `C` ≤۱۲۰، `D` ≤۲۵۰، `F` بیشتر |
| افت و لرزش UDP | با `--udp`: دیتاگرام‌ها از تونل به همان اندپوینت می‌روند و برمی‌گردند؛ هر شمارهٔ ترتیبی که نیاید افت حساب می‌شود |

اندپوینت فقط روی `127.0.0.1` گوش می‌دهد، در **هر دو موتور**، و اگزیت پورتش را
در دست‌دادن اولیهٔ اتصال اعلام می‌کند — پس عوض کردن `speedtest_port` (یا `0`
برای خاموش‌کردن اندپوینت) روی اگزیت، بدون دست‌زدن به رله کار می‌کند. اگر تونل
بالا نباشد، `simurgh speedtest` همان را می‌گوید و با کد ۳ خارج می‌شود؛ عدد
از خودش درنمی‌آورد.

`--json` همه‌چیز را برمی‌گرداند:

```json
{
  "seconds": 3.0, "streams": 1,
  "download_mbps": 3655.3, "upload_mbps": 1528.8,
  "latency": {"idle_ms": 0.6, "loaded_ms": 12.4, "increase_ms": 11.9,
              "jitter_ms": 6.5, "loaded_p95_ms": 25.9, "grade": "A"},
  "udp": {"sent": 200, "received": 200, "loss_percent": 0.0,
          "rtt_ms": 0.3, "jitter_ms": 0.1}
}
```

## لینک‌های اتصال

یک لینک اتصال، توکن و اندپوینت را در یک رشته جا می‌دهد:

```
simurgh://<host>:<panel-port>/setup?u=<panel-user>&p=<base64 password>#<name>
```

* روی **اگزیت**: `simurgh link --show` لینک یک رلهٔ جدید را چاپ می‌کند.
* روی **رلهٔ معکوس**: همان فرمان لینک مخصوص اگزیت را چاپ می‌کند.
* روی سرور دیگر: `simurgh join '<link>'` کانفیگ را می‌سازد؛ `--host <ip>` برای
  تغییر آدرس و `--force` برای بازنویسی کانفیگ موجود.

لینک‌ها را محرمانه بدانید: توکن تونل داخل آن‌هاست.

## متریک‌ها و به‌روزرسانی

### متریک‌های Prometheus (`/metrics`)

هر نودی که پنل دارد، متن Prometheus را روی همان پورت بیرون می‌دهد:

```bash
curl -u admin:password http://127.0.0.1:8787/metrics
```

| متریک | معنی |
|---|---|
| `simurgh_up` / `simurgh_uptime_seconds` | نود پاسخ می‌دهد و از چه زمانی |
| `simurgh_tunnel_connected`، `simurgh_tunnel_connections`، `simurgh_tunnel_rtt_seconds` | وضعیت تونل(ها) به طرف مقابل |
| `simurgh_streams`، `simurgh_reconnects_total`، `simurgh_blocked_total` | استریم‌های زنده، وصل‌شدن‌های دوباره، کاربرانی که کوتا ردشان کرده |
| `simurgh_bytes_in_total`، `simurgh_bytes_out_total` | ترافیک کاربران |
| `simurgh_mapping_*{key,name,listen,target}` | بایت، اتصال، فعال، خطا و `up` هر mapping |
| `simurgh_traffic_bytes_total{key,period}` | دفتر کل پایدار (`today` / `month` / `total`) |
| `simurgh_quota_*{key,period}` | سقف کوتا، مصرف‌شده و تمام‌شدن آن |
| `simurgh_exit_*{endpoint}` | سلامت استخر: اندپوینت جواب می‌دهد؟ RTT چقدر است؟ |
| `simurgh_panel_requests_total`، `simurgh_panel_lockouts_total`، `simurgh_panel_failed_logins` | ترافیک پنل، آدرس‌هایی که بعد از چند رمز اشتباه قفل شده‌اند، و تعداد رمزهای غلط در همین لحظه |
| `simurgh_alerts_sent_total`، `simurgh_alerts_failed_total`، `simurgh_alerts_enabled` | هشدارهای رسیده، هشدارهای ناموفق، و اینکه اصلاً کانالی تنظیم شده یا نه |

احراز هویت مثل خود پنل است (Basic auth، کوکی نشست یا لینک `?k=`)، پس همان
اطلاعات پنل برای اسکرپر کافی است.  همهٔ عددها از همان وضعیتی خوانده می‌شوند که
پنل نشان می‌دهد، یعنی متریک‌ها با **هر دو موتور** کار می‌کنند: با موتور
پایتون مستقیم از خود نود و با موتور Go از `state.json` که آن موتور به‌روز
نگه می‌دارد.

### `simurgh update`

```bash
simurgh update            # نصب جدیدترین ریلیز
simurgh update --check     # فقط گزارش (کد خروج ۳ اگر نسخهٔ جدید باشد)
simurgh update --check --json
```

خودش تشخیص می‌دهد نصب از چه نوعی است:

* **چک‌اوت گیت** — تگ‌ها را می‌گیرد، جدیدترین تگ ریلیز را checkout می‌کند و
  موتور Go را دوباره می‌سازد (`--no-rebuild` این مرحله را رد می‌کند)؛
* **نصب بسته‌ای** — فایل مناسب سیستم‌عامل و معماری را دانلود می‌کند، SHA-256
  آن را با `SHA256SUMS.txt` همان ریلیز می‌سنجد و باینری در حال اجرا را
  اتمیک جایگزین می‌کند و نسخهٔ قبلی را به‌عنوان `simurgh-go.bak` نگه می‌دارد؛
* **نصب pip** — دستور `pip install -U simurgh-tunnel` را اجرا می‌کند.

بدون اینترنت چیزی را عوض نمی‌کند و صریح می‌گوید.  بعد از به‌روزرسانی،
`simurgh restart` نسخهٔ جدید را بالا می‌آورد.

## هشدارها (Alerts)

اپراتور باید خرابی تونل را از خود تونل بشنود، نه از زبان مشتری. هر دو نقش
همین کلیدها را می‌گیرند، هم در `relay.toml` و هم در `exit.toml`:

```toml
telegram_token = "8123456:AAH…"        # از @BotFather
telegram_chat  = "-1001234567890"      # چتی که ربات در آن پیام می‌گذارد
# telegram_api = "http://127.0.0.1:8081"   # سرور Bot API محلی (اختیاری)
alert_webhook  = "https://hooks.example.com/simurgh"   # هر جایی که JSON می‌گیرد
alert_events   = ["connected", "disconnected", "quota", "cert", "error"]
```

| کلید | پیش‌فرض | معنی |
|---|---|---|
| `telegram_token` | — | توکن ربات؛ همراه `telegram_chat` لازم است |
| `telegram_chat` | — | شناسهٔ چت (شناسهٔ گروه با `-` شروع می‌شود) |
| `telegram_api` | `https://api.telegram.org` | ریشهٔ Bot API؛ اگر API عمومی فیلتر است، سرور خودتان را بدهید |
| `alert_webhook` | — | آدرسی که برای هر هشدار یک `POST` با بدنهٔ JSON می‌گیرد (Slack، Discord، ntfy، سرویس داخلی) |
| `alert_events` | `connected, disconnected, quota, cert, error` | کدام رویدادها فرستاده شوند؛ `["all"]` یعنی همه |

بدنهٔ وب‌هوک برای هر هشدار:

```json
{"event": "quota", "level": "warning", "text": "[ir-tehran] mapping tcp:0.0.0.0:443/… reached its 10.0 MB/month quota (block)",
 "host": "ir-tehran", "time": 1792163305.35, "mapping": "tcp:…", "used": 10485760, "limit": 10485760}
```

| رویداد | کِی فرستاده می‌شود | فیلدهای اضافه |
|---|---|---|
| `started` / `stopped` | سرویس بالا می‌آید یا خاموش می‌شود | `pid` (موتور Go) |
| `connected` / `disconnected` | تونل به طرف مقابل وصل می‌شود یا می‌افتد | `rtt_ms` و آدرس طرف مقابل |
| `quota` | یک mapping به سقف کوتایش می‌رسد (`block`، `throttle` یا `warn`) | `mapping`، `used`، `limit` |
| `throttle` | یک mapping به‌خاطر کوتا به ۱۲۸ کیلوبایت بر ثانیه محدود شده | `mapping` |
| `cert` | گواهی‌ای که این نود ارائه می‌دهد تا **۱۴ روز** دیگر منقضی می‌شود (روزی یک بار برای هر فایل) | `cert`، `days` |
| `login` | پنل بعد از چند رمز اشتباه یک آدرس را قفل کرده | `peer` |
| `error` | خطای نود، یا خروج موتور Go و شروع دوبارهٔ آن | `exit_code`، `restarts` |
| `test` | `simurgh alert test` | — |

هشدارها در صف می‌نشینند و از یک ترد کارگر فرستاده می‌شوند، پس اندپوینت کند
(یا مرده) هیچ‌وقت دادهٔ کاربران را معطل نمی‌کند؛ رویدادهای یکسان با یک
خنک‌سازی ۲۰ ثانیه‌ای ادغام می‌شوند تا تونل ناپایدار چت را پر نکند.  نودی که
تازه خاموش شده، صف خودش را قبل از خروج خالی می‌کند.

```bash
simurgh alert status                  # کدام کانال و کدام رویدادها فعال است
simurgh alert test                    # همین حالا یک پیام می‌فرستد (اگر نشد، کد خروج ۱)
simurgh alert events                  # نمایش فهرست
simurgh alert events quota cert error # نوشتن فهرست تازه (بعدش: simurgh restart)
simurgh alert status --role exit
```

## گواهی‌ها (Let's Encrypt)

هر اندپوینت `tls`/`wss` به گواهی نیاز دارد و سه راه برای دادنش هست:

۱. **`cert_auto = true`** (پیش‌فرض) — یک گواهی خودامضا در اولین اجرا ساخته
   می‌شود. برای خودِ تونل کامل است: هر دو طرف TLS حرف می‌زنند، رله اثرانگشت را
   پین می‌کند و کسی هشدار «نامعتبر» نمی‌بیند. ولی برای پنل یا سایتی که پشت
   تونل است قابل استفاده نیست.
۲. **فایل‌های خودتان** — `cert_file` / `key_file` بالای فایل (یا داخل یک بلوک
   `[[listen]]` برای سروری که چند دامنه دارد). همان مسیرهایی که ابزارتان
   ساخته را بدهید:

   ```toml
   cert_auto = false
   cert_file = "/etc/letsencrypt/live/panel.example.com/fullchain.pem"
   key_file  = "/etc/letsencrypt/live/panel.example.com/privkey.pem"
   ```

   بعد از هر تمدید سرویس را ری‌استارت کنید (`simurgh restart`)؛ اگر یادتان
   برود، همان هشدار `cert` در بخش بالا ۱۴ روز قبل از دردسر خبر می‌دهد.
۳. **`simurgh cert issue`** — بگذارید سیمورغ `acme.sh` (ترجیح‌داده‌شده: یک
   اسکریپت شل، پس روی سرور فیلترشده هم نصب می‌شود) یا `certbot` را برایتان
   اجرا کند، نتیجه را در کانفیگ بنویسد و هوک تمدید نصب کند:

   ```bash
   sudo simurgh cert issue panel.example.com --email me@example.com \
        --webroot /var/www/html          # nginx/caddy همان را سرو می‌کند
   sudo simurgh cert issue panel.example.com --standalone   # پورت ۸۰ آزاد است
   sudo simurgh cert issue panel.example.com --staging      # آزمایش با CA تستی
   sudo simurgh cert issue panel.example.com --port 8443     # فقط همین لیسنر
   ```

   گواهی در `exit.toml` نوشته می‌شود (یا با `--role relay` در بلوک
   `[tunnel]` رله)، `cert_auto` خاموش می‌شود تا موتور هرگز روی آن گواهی
   خودامضا نگذارد، و `acme.sh --install-cert --reloadcmd "systemctl restart
   simurgh-exit"` یعنی تمدید بعدی خودش سرویس را ری‌استارت می‌کند. با
   `--no-write` گواهی گرفته می‌شود ولی کانفیگ دست‌نخورده می‌ماند و با `--apply`
   همان هوک همین حالا اجرا می‌شود (وقتی سرویس‌منیجری در کار نیست، به‌کار می‌آید).

   ```bash
   simurgh cert                     # چه چیزی در استفاده است: مسیر، روز باقی‌مانده، اثرانگشت
   simurgh cert renew               # اجرای تمدید خودِ کلاینت (= همان کرون)
   simurgh cert status --role relay
   simurgh cert status --json       # همان، برای اسکریپت یا مانیتورینگ
   ```

   خط‌هایی که `(self-signed)` خورده‌اند از `cert_auto` می‌آیند؛ برای خودِ تونل
   مشکلی ندارند و `simurgh cert issue <domain>` آن‌ها را با گواهی واقعی عوض
   می‌کند. `simurgh cert status` اگر چیزی نبود، خوانده نشد یا کمتر از ۱۴ روز
   مانده باشد با کد ۱ خارج می‌شود، پس در اسکریپت پایش هم قابل استفاده است.

   روی لیسنری که `cert_file` مخصوص خودش را دارد، `simurgh cert issue` بدون
   `--port` آن بلوک را دست نمی‌زند و همان را گزارش می‌کند.

### سخت‌ترشدن پنل

* **رمزهای اشتباه** برای هر آدرس شمرده می‌شوند. رمز غلط پنجم آن آدرس را
  **۳۰۰ ثانیه** قفل می‌کند (پاسخ `429`) — یعنی حدس‌زدن بی‌فایده می‌شود — و
  هشدار `login` می‌گوید تلاش از کجا بوده. ورود موفق شمارنده را پاک می‌کند و
  `simurgh_panel_lockouts_total` تعداد دفعات را می‌شمارد.
* پنل **هیچ‌وقت توکن یا توکن ربات را چاپ نمی‌کند**؛ `simurgh alert status`
  آن را ماسک می‌کند (`1234…ew11`).
* لینک `?k=<رمز>` هنوز برای ورود یک‌کلیکی کار می‌کند، ولی رمز در تاریخچهٔ
  مرورگر می‌ماند؛ بهتر است از همان کوکی نشستی که این لینک می‌سازد استفاده
  کنید یا Basic auth بدهید.

| متغیر | معنی |
|---|---|
| `SIMURGH_HOME` | پوشهٔ کانفیگ (پیش‌فرض `/etc/simurgh`) |
| `SIMURGH_ALLOW_NONROOT` | `1` — اجازهٔ نصب به‌عنوان کاربر عادی (بدون systemd) |
| `SIMURGH_REF` / `--ref` | رِفی که نصاب دانلود می‌کند (برنچ یا تگ) |
