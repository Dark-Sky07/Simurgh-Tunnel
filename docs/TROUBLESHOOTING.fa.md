# عیب‌یابی

[English](TROUBLESHOOTING.md) · **فارسی**

<div dir="rtl">

اول از همه عیب‌یاب داخلی را اجرا کنید — کانفیگ، توکن، فایروال، شنونده‌ها و لاگ را
بررسی می‌کند و راهنمای عملی می‌دهد:

```bash
simurgh doctor
simurgh logs -f          # لاگ زنده (/etc/simurgh/logs/*.log)
```

---

## پنل باز نمی‌شود

* پورت را باز کنید: `ufw allow 8787` (یا `firewall-cmd --add-port=8787/tcp`).
* وضعیت سرویس: `systemctl status simurgh-relay` یا `simurgh status`.
* آدرس و رمز پنل در اولین اجرا چاپ می‌شود و در `/etc/simurgh/state.json` ذخیره
  است؛ `simurgh status` هم نشانش می‌دهد.
* ورود یک‌کلیکی: `http://<server>:8787/?k=<رمز-پنل>`.

## تونل بالا نمی‌آید (حالت مستقیم)

۱. روی **هر دو** سرور `simurgh doctor` را اجرا کنید.
۲. توکن باید بایت‌به‌بایت یکسان باشد (در صورت شک، لینک اتصال را دوباره بگیرید).
۳. پورت تونل باید روی **سرور خارج** باز باشد (مثلاً `443/tcp`) — همان پورتی که
   `[[listen]]` روی آن گوش می‌دهد.
۴. `simurgh status` روی رله: فیلدهای `last_error` و `bind_errors` می‌گویند آخرین
   مشکل چه بوده است.
۵. اگر اثرانگشت گواهی پین شده باشد، رله هر گواهی دیگری را رد می‌کند: بعد از
   تغییر گواهی، لینک را دوباره بسازید، یا موقتاً در `[exit]` مقدار
   `insecure_skip_verify = true` بگذارید تا مطمئن شوید مشکل از پین بوده است.
۶. `strict_ports = true` روی اگزیت پورت‌هایی که به رله پیشنهاد نشده‌اند را رد
   می‌کند — پورت را به `push_ports` اضافه کنید یا سخت‌گیری را خاموش کنید.

## تونل بالا نمی‌آید (حالت معکوس)

در حالت معکوس **اگزیت به رله وصل می‌شود**، پس بررسی‌ها برعکس می‌شوند:

۱. روی رله: `dial = "exit"` در `relay.toml` باشد و پورت `[tunnel]` (مثلاً ۸۴۴۳)
   در فایروال باز باشد.
۲. روی اگزیت: لاگ باید `dialling the relay at <ip>:<port>` را نشان دهد؛ خطای
   `cannot reach the relay` یعنی آدرس یا فایروال اشتباه است.
۳. توکن اشتباه در هر طرف، بی‌صدا رد می‌شود و شنونده صفحهٔ طعمه را سرو می‌کند —
   توکن را بررسی کنید.
۴. اگر گواهی رله را عوض کرده‌اید، کانفیگ اگزیت را با
   `simurgh join '<new link>' --force` تازه کنید تا اثرانگشت بخواند.
۵. بعد از `systemctl restart simurgh-relay`، اگزیت در چند ثانیه خودش برمی‌گردد.

## یک پورت روی رله کار نمی‌کند

```bash
simurgh mapping list          # فعال است؟ bind شده؟
```

* سرویس باید روی `127.0.0.1:<target_port>` **روی سرور خارج** گوش بدهد (اگزیت به
  همان وصل می‌شود). اگر سرویس جای دیگری است، `--target-host 10.0.0.5` بدهید.
* مپینگ جدید را پنل بلافاصله اعمال می‌کند؛ CLI فقط «ذخیره شد» را چاپ می‌کند —
  اگر فایل را دستی ویرایش کرده‌اید `simurgh restart` بزنید.
* `simurgh mapping add` اگر پورت اشغال باشد هشدار می‌دهد؛ با
  `ss -ltnp | grep <port>` بررسی کنید.
* سرویس‌های UDP به `udp = true` نیاز دارند (`simurgh mapping add 2096 2096 --udp`).

## کاربران وصل می‌شوند ولی صفحه نمی‌گیرند

* روی رله تست کنید: `curl -v http://127.0.0.1:<iran-port>/` — اگر این کار کرد،
  تونل و اگزیت سالم‌اند و مشکل از سمت کاربر است (پورت/SNI اشتباه یا رد شدن توسط
  پنل).
* بعضی پنل‌ها فقط روی یک آدرس مشخص گوش می‌دهند؛ مطمئن شوید سرویس روی `127.0.0.1`
  (یا همان `target_host`) بالا است.
* پنل‌هایی که IP مبدأ را بررسی می‌کنند، `127.0.0.1` می‌بینند مگر `proxy_protocol`
  را روی اگزیت روشن کنید و پنل هم از PROXY protocol پشتیبانی کند.

## سرعت کمتر از انتظار است

```bash
simurgh speedtest        # اندازه‌گیری از داخل خود تونل
```

* اگر تونل سریع است، گلوگاه سرور خارج، پنل یا لینک کاربر است.
* روی لینک‌های خیلی پرسرعت (بیش از ۱ گیگابیت) `stream_window` را بالاتر ببرید
  (مثلاً `524288`) و `chunk = 65536` را نگه دارید.
* در `simurgh status` شمارندهٔ reconnect را ببینید: قطع/وصل‌های مکرر بیشتر از هر
  تنظیمی سرعت را کم می‌کنند.

## رله می‌گوید «پورت اشغال است»

پروسهٔ دیگری (یا نسخهٔ قدیمی) آن را گرفته است:

```bash
ss -ltnp | grep -E ':(443|8787)\b'
systemctl stop simurgh-relay    # و دوباره start
```

## هیچ‌چیز کار نمی‌کند و می‌خواهم از صفر شروع کنم

```bash
sudo simurgh uninstall --purge     # حذف سرویس‌ها، کانفیگ‌ها و گواهی‌ها
sudo bash install.sh --role relay --exit <foreign-ip>:443
```

## جمع‌آوری اطلاعات برای گزارش مشکل

```bash
simurgh --version
simurgh doctor
simurgh status
tail -n 100 /etc/simurgh/logs/relay.log     # یا exit.log
```

لطفاً قبل از انتشار عمومی لاگ‌ها، توکن و آدرس‌ها را حذف کنید.
