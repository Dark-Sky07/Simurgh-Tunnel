# پنل وب

[English](PANEL.md) · **فارسی**

پنل، صفحه‌ای است که تونل دربارهٔ خودش سرو می‌کند: نقشهٔ دو سر تونل، عددهای پشتشان
و دکمه‌هایی که اپراتور ساعت سه صبح سراغ‌شان می‌رود. پنل جزئی از بسته است — یک فایل
پایتون (`simurgh/panel.py`)، یک فایل داده (`simurgh/layout.py`)، یک جدول رشته
(`simurgh/panel_i18n.py`) و فایل‌های HTML/CSS/JavaScript، manifest و آیکن در
`simurgh/assets/`. نه مرحلهٔ build دارد، نه فریم‌ورک، نه CDN و نه وابستگی
جاوااسکریپتی: هیچ‌کدام از چیزهایی که پنل نشان می‌دهد برای بار شدن به اینترنت نیاز
ندارد. از v3.2.5 نصاب این فایل‌ها را داخل پکیج نصب‌شدهٔ Python هم بررسی می‌کند تا
پاسخ سالم `/healthz` نتواند نصب ناقص داشبورد را مخفی کند.

## باز کردن پنل

```bash
simurgh web                       # فقط پنل، کنار نود در حال اجرا
simurgh web --link                # …و یک لینک ورود یک‌بارمصرف روی خروجی
simurgh web --port 9000 --host 127.0.0.1
```

راه معمول، سرویس است: `simurgh start` هم نود و هم پنل را اجرا می‌کند و پورت پنل
از `panel_port` در `relay.toml` می‌آید (پیش‌فرض `8787`). روی اگزیت هم اگر از منو
اجرا کنید، پنل روی همان پورت پنل رله سرو می‌شود.

| راه ورود | چطور |
|---|---|
| پرسش رمز | `http://<ip>:8787` — HTTP Basic، مناسب اسکریپت و `curl` |
| لینک یک‌کلیکی قدیمی | `http://<ip>:8787/?k=رمز-پنل` — رمز را با کوکی عوض می‌کند و به `/` هدایت می‌شود |
| فرم ورود | `http://<ip>:8787/login` — فرم واقعی، `EN / فا` |
| لینک یک‌بارمصرف | `simurgh web --link` یا صفحهٔ امنیت: یک‌بار، ۱۰ دقیقه |

> اگر سرور از اینترنت قابل دسترسی است، پنل را پشت فایروال یا تونل SSH بگذارید.
> پنل احراز هویت دارد و سخت‌شده است، ولی همچنان یک control plane است:
> `ssh -L 8787:127.0.0.1:8787 root@server` و در مرورگر
> `http://127.0.0.1:8787`.

## نقشه

داشبورد تونل را به شکل همان پرنده‌ای می‌کشد که نامش از اوست:

```
        رله (بال چپ)                   بدنهٔ تونل                    اگزیت (بال راست)
   ┌─────────────────┐   ╔═════════════════════════╗   ┌─────────────────┐
   │ کشور · نام      │   ║  tls :443  · rtt 12 ms  ║   │ کشور · نام      │
   │ آپ‌تایم · کانکشن │   ║  استخر: ۲ اگزیت، ۱ زنده ║   │ لیسن · تونل‌ها  │
   └─────────────────┘   ╚═════════════════════════╝   └─────────────────┘
            ╲                    پرهای دم                          ╱
             ╲  443 ●── کوتا ۵۰٪ ─▶ 127.0.0.1:8443  ↓ 2.1 Mb/s   ╱
```

* **بال‌ها** — نام هر سر، آپ‌تایم، تعداد کانکشن و آخرین خطا. هر بالی که طرفش
  پایین باشد کم‌رنگ می‌شود و دلیلش روی hover می‌آید.
* **بدنه** — کریر فعال، پورت، RTT و اینکه استخر چند اندپوینت می‌شناسد و چند
  تا زنده است. اندپوینت جانشین حلقهٔ توخالی است و فعالِ پرشده؛ hover وضعیت
  جانشینی هرکدام را نشان می‌دهد.
* **پرهای دم** — یکی برای هر مپینگ: پروتکل، پورت شنیدن، مقصد، حلقهٔ کوتا، نرخ
  لحظه‌ای و اسپارک‌لاین چند دقیقهٔ اخیر. پری که ترافیک از آن رد شود روشن می‌شود.
* **نمودار** — مجموع ورودی/خروجی نیم ساعت گذشته، از تاریخچهٔ خود پنل
  (`layout.History`؛ نمونه هر ۲ ثانیه، ارسال با دقت ۱۰ ثانیه).

همهٔ چیزهایی که روی صفحه می‌بینید از یک درخواست می‌آید: `GET /api/layout` هر دو
ثانیه (و هرگز وقتی تب مرورگر مخفی است).

## جفت‌سازی کامل از پنل

نصاب واحد می‌تواند رلهٔ مستقیم ایران را پیش از ساخته‌شدن اگزیت خارج، با
`unpaired = true` نصب کند. داشبورد وضعیت **جفت‌نشده** را نشان می‌دهد و تونل رله
بی‌حرکت می‌ماند؛ این وضعیت عمدی است، نه نصب ناموفق.

### حالت مستقیم

1. در **اگزیت** به **Pair ← Create a setup link** بروید و لینک را بسازید. اگر
   پنل از SSH/NAT باز شده است، ابتدا `IP/domain[:port]` عمومی پنل را وارد کنید؛
   سرور دیگر به همین آدرس وصل می‌شود.
2. لینک `simurgh://…` را در **صفحهٔ Pair رله** بچسبانید و **Pair** را بزنید.
3. رله توکن، آدرس/استخر اگزیت، fingerprint گواهی و مپینگ‌های اعلام‌شده را دریافت
   می‌کند. پورت پنل، موتور، محدودیت‌ها و مپینگ‌های فعلی رله حفظ می‌شوند. موتور
   Python نتیجه را زنده اعمال می‌کند و بکاپ در `relay.toml.bak-pair` می‌ماند.

`POST /api/setup-link {"host": "203.0.113.9:8787"}` روی سرور ارائه‌دهنده لینک
می‌سازد و `POST /api/pair {"link": "simurgh://…"}` آن را روی سرور گیرنده وارد
می‌کند. هر دو به احراز هویت معمول پنل نیاز دارند. رلهٔ مستقیم، لینک مخصوص اگزیت
معکوس و لینک خالی/خراب را رد می‌کند. روی رلهٔ جفت‌شده، **Replace exit** پیش از
جایگزینی توکن، نشانی و fingerprint تأیید صریح می‌گیرد؛ تنظیمات پنل و پورت‌های
محلی حفظ می‌شوند.

### حالت معکوس

در **Settings** رله، **آغازکنندهٔ اتصال تونل** را `exit` انتخاب کنید، حامل، پورت و
مسیر شنوندهٔ معکوس را تنظیم و ذخیره کنید و ری‌استارت کنید. رله در صورت نیاز توکن
تونل می‌سازد و صفحهٔ Pair آن می‌تواند لینک ارائه دهد. این لینک را در کارت
**Connect to a reverse relay** روی اگزیت خارج وارد کنید. این کار عمداً شنونده‌های
تونل اگزیت را جایگزین می‌کند، موتور و محدودیت‌های محلی را حفظ می‌کند، بکاپ
`exit.toml.bak-pair` می‌سازد و ری‌استارت از **Tools** را می‌خواهد.

لینک راه‌اندازی حاوی رمز پنل و payload حاوی رمز تونل است. از کانال خصوصی استفاده
کنید و خود پنل را پشت فایروال یا تونل SSH نگه دارید.

## ویزارد

ساختن دستی تونل یعنی درست درآوردن کریر، پورت، مسیر، split و اولین مپینگ در هر دو
سر. ویزارد این را به نقشه‌ای تبدیل می‌کند که پیش از هر نوشتنی می‌خوانید:

1. **پیش‌نمایش** — `POST /api/wizard {"step": "preview", "plan": {...}}` دیف را
   نسبت به کانفیگ فعلی برمی‌گرداند (`[exit] carrier tls -> wss`) و هیچ نمی‌نویسد.
   نقشهٔ رد‌شده دلیلش را می‌گوید: کریر ناشناس، پورتی بیرون ۱ تا ۶۵۵۳۵، مپینگی که
   `listen:target` نیست، یا split‌ای که عدد نیست.
2. **اعمال** — فایل فعلی در `<config>.bak-wizard` کپی و نقشه نوشته می‌شود. برای
   تغییر شنونده یا ترانسپورت، در صورت نیاز از **Tools** ری‌استارت کنید.
3. **بازگردانی** — بکاپ برمی‌گردد و دوباره بارگذاری می‌شود. یک کلیک، و فایل قبلی
   بعد از آن هم سر جایش می‌ماند.

نقشه عمداً کوچک است: `carrier` (tls، wss، raw، plain، udp)، `port`، `host`،
`path`، `split` و `mapping` (`listen:target`). تنظیمات روزمره در **Settings**
هستند و فایل کانفیگ برای گزینه‌های پیشرفتهٔ بدون کنترل اختصاصی باقی می‌ماند.

## تم، زبان و گوشی

* `night` پیش‌فرض است و `dawn` تم روشن. این انتخاب (مثل زبان) در هر مرورگر ذخیره
  می‌شود (`localStorage`).
* storage فقط حافظهٔ ترجیحات است: اگر سیاست مرورگر آن را مسدود کند، پنل با
  پیش‌فرض‌ها به‌کارش ادامه می‌دهد. view ذخیره‌شدهٔ ناشناخته نیز به داشبورد
  برمی‌گردد و همهٔ بخش‌ها را مخفی نمی‌کند.
* انگلیسی و فارسی با هم می‌آیند (`simurgh/panel_i18n.py`)، برای فارسی `dir` به
  `rtl` می‌رود و اگر این دو جدول از هم دور بیفتند یک تستfail می‌شود.
* زیر ۷۲۰ پیکسل سایدبار به نوار پایین تبدیل می‌شود، نقشه بال‌ها را روی بدنه
  می‌چیند و جدول‌ها افقی اسکرول می‌شوند — پنل روی گوشی کار می‌کند، همان‌جایی که
  بیشتر این سرورها اول از همه چک می‌شوند.
* به‌شکل وب‌اپ هم نصب می‌شود: `/manifest.webmanifest` و آیکن.

## چه چیزی امنش نگه می‌دارد

| قاعده | چرا |
|---|---|
| CSP سخت (`default-src 'none'`)، بدون اسکریپت inline یا استایل خارجی؛ style attributeهای خود پنل مجازند | نه کد یا استایل شخص ثالث اجرا می‌شود و نه چیدمان خود پنل خراب می‌شود |
| asset‌ها با نام از بسته سرو می‌شوند | `read_asset` هر چیزی که مسیر داشته باشد را رد می‌کند؛ traversal ممکن نیست |
| `Cache-Control: no-store` روی هر پاسخ API و روی کد | مرورگر هیچ‌وقت عدد یا صفحهٔ کهنه نشان نمی‌دهد |
| `X-Frame-Options: DENY` | پنل را نمی‌توان در صفحهٔ فیشینگ قاب گرفت |
| پنج ارسال صریح ورود ناموفق از یک آدرس ← قفل ۳۰۰ ثانیه‌ای (`429`)؛ چالش ناشناس شمرده نمی‌شود | جلوگیری از brute force بدون قفل‌شدن در بازدید عادی، روی پنل و `/metrics` |
| لینک‌های یک‌بارمصرف هش‌شده، یک‌بار قابل‌استفاده، TTL ده‌دقیقه‌ای، حداکثر ۵ لینک باز | لینک لو‌رفته بی‌ارزش است؛ `revoke` همه را دور می‌ریزد |
| توکن‌ها هرجا چاپ شوند ماسک می‌شوند | لاگ و پنل هیچ‌وقت رمز چاپ نمی‌کنند |
| پنل هرگز در مسیر داده نیست | می‌توان متوقف، ری‌استارت یا خرابش کرد بدون آنکه ترافیک آسیب ببیند |

## نصب به‌روزرسانی

به **Tools ← Updates** بروید. **Check for updates** فقط آخرین ریلیز گیت‌هاب را می‌خواند. **Install update** پس از تأیید، کد Python و موتور Go متناسب دارای checksum را نصب می‌کند، پاسخ را به مرورگر می‌رساند و سپس سرویس را ری‌استارت می‌کند. صفحه با `/healthz` منتظر برگشتن واقعی پنل می‌ماند، نسخهٔ گزارش‌شده را با ریلیز نصب‌شده تطبیق می‌دهد و فقط بعد از اجرای نسخهٔ جدید تازه‌سازی می‌شود. اگر پروسهٔ قدیمی همچنان سالم بماند یا شنونده برنگردد، شکست ری‌استارت را گزارش می‌کند و نسخهٔ قدیمی را موفقیت تلقی نمی‌کند.

فقط یک ارتقا می‌تواند هم‌زمان اجرا شود. ارتقا به `relay.toml`، `exit.toml`، وضعیت pairing، مپینگ‌ها یا رمزهای پنل دست نمی‌زند. کشف ریلیز ابتدا API گیت‌هاب و سپس، اگر API rate-limit یا خارج از دسترس باشد، ریدایرکت اعتبارسنجی‌شدهٔ `/releases/latest` را امتحان می‌کند؛ دانلود مستقیم موتور همچنان checksum SHA-256 منطبق همان ریلیز را لازم دارد. همین عملیات در `simurgh menu` گزینهٔ **17** است؛ برای اتوماسیون نیز `simurgh update --restart` بعد از ری‌استارت سلامت پنل را الزامی می‌کند. اگر کنترل سرویس در دسترس نباشد، فایل‌ها به‌روز می‌شوند و رابط برای ری‌استارت دستی راهنمایی می‌کند.

## API

هر کاری که پنل می‌کند یکی از این‌هاست؛ همه احراز هویت دارند (Basic auth یا کوکی
نشستی که ورود می‌دهد):

| متد | مسیر | کار |
|---|---|---|
| GET | `/` | صفحهٔ shell (رشته‌ها در یک بلوک دادهٔ JSON می‌آیند) |
| GET | `/app.css`، `/app.js`، `/login.js`، `/favicon.ico`، `/assets/<name>`، `/manifest.webmanifest` | asset‌ها، مستقیم از بسته |
| GET | `/api/status` | وضعیت نود + پنل (پاسخ کوچک) |
| GET | `/api/layout` | نقشه، کارت‌ها، نمودار و نرخ‌ها (پاسخ بزرگ) |
| GET | `/api/config` | کانفیگ قابل‌ویرایش |
| POST | `/api/config` | نوشتن آن |
| POST | `/api/mappings` | افزودن/حذف/خاموش‌روشن مپینگ، اعمال زنده |
| POST | `/api/action` | ری‌استارت/توقف/شروع/اتصال دوباره یا تست سرعت |
| POST | `/api/tune` | اعمال پروفایل کارایی (`gaming`، `balanced`، `speed`) |
| POST | `/api/setup-link` | ساخت لینک جفت‌سازی روی اگزیت یا رلهٔ معکوس |
| POST | `/api/pair` | ورود لینک رلهٔ مستقیم یا اگزیت معکوس |
| POST | `/api/wizard` | پیش‌نمایش/اعمال/بازگردانی نقشهٔ تونل |
| POST | `/api/login-token` | ساخت لینک ورود یک‌بارمصرف |
| POST | `/api/join` | payload احرازشده‌ای که سرور گیرنده برای جفت‌سازی دریافت می‌کند |
| GET | `/api/update` | یک بار پرسیدن از گیت‌هاب که نسخهٔ تازه‌تری هست یا نه |
| POST | `/api/update` | نصب نسخهٔ تازه و زمان‌بندی ری‌استارت بعد از ارسال پاسخ |
| GET | `/api/logs` | دم لاگ با تعداد خط محدود |
| GET | `/login`، `POST /login`، `GET /logout` | فرم، پاسخ فرم و خداحافظی |
| GET | `/metrics` | متن Prometheus برای همان اعداد (`simurgh_listen_*`، `simurgh_panel_*`، …) |
| GET | `/healthz` | زنده‌بودن، بدون احراز هویت، برای watchdog |

اگر می‌خواهید فرانت‌اند خودتان را بنویسید، همان `/api/layout` را بخوانید: JSON است،
همان داده‌ای است که نقشهٔ همراه پروژه می‌کشد، و `simurgh/layout.py` تمام لایهٔ
ترجمه بین آن و `status()` نود است.

## نوشتن روی آن

پنل، رابط معمول تنظیمات بعد از نصب واحد است. هر نوشتنی از همان `config.save_*` و
اعتبارسنجی CLI عبور می‌کند؛ فایل‌ها اتمیک نوشته می‌شوند و جفت‌سازی و ویزارد بکاپ
دارند. CLI برای عیب‌یابی، بازیابی و اتوماسیون پیشرفته باقی است، اما برای
جفت‌سازی، مدیریت پورت یا تنظیمات معمول لازم نیست.
