# اتصال دو سرور و تست واقعی تونل

[English](CONNECTING.md) · **فارسی**

<div dir="rtl">

این راهنما دو سرور موجود را از طریق پنل به هم وصل می‌کند و بعد اتصال را با یک
پاسخ واقعی، تست سرعت و شمارنده‌های ترافیک بررسی می‌کند. برای شروع نیازی به حذف یا
بازنویسی `/etc/simurgh` نیست. در تمام مثال‌ها `EXIT_IP` و `IRAN_IP` را
با IP عمومی واقعی سرور خارج و ایران جایگزین کنید.

## ۱) نقش‌ها و پورت‌ها را مشخص کنید

در حالت معمول **Direct**:

```text
کاربر ──► IP سرور ایران:8443 ── تونل TLS ──► سرور خارج ──► 127.0.0.1:8443
                              پورت تونل:443
```

- **رله / ایران:** ورودی کاربران را می‌گیرد و به خارج وصل می‌شود.
- **اگزیت / خارج:** اتصال تونل را قبول می‌کند و ترافیک را به سرویس مقصد می‌رساند.
- **پورت تونل:** مثلاً `443/TCP` روی خارج؛ فقط برای ارتباط رله با اگزیت است.
- **پورت کاربر:** مثلاً `8443/TCP` روی ایران؛ کاربران به همین پورت وصل می‌شوند.
- **پورت پنل:** پیش‌فرض `8787/TCP`؛ این پورت با پورت تونل فرق دارد و نباید دائماً
  برای همهٔ اینترنت باز بماند.

اگر `443` روی خارج اشغال است، پورت آزاد دیگری مثل `4443` انتخاب کنید و همان را در
Settings اگزیت و فایروال وارد کنید. برای شروع `tls` و یک tunnel connection را
تغییر ندهید؛ بعد از سالم‌شدن مسیر می‌توانید گزینه‌های دیگر را جداگانه بسنجید.

## ۲) نصب یا ارتقا؛ یک فرمان برای هر دو سرور

اگر Simurgh قبلاً نصب شده، به **Tools → Check for updates** بروید و آخرین نسخه را
نصب کنید. برای نصب تازه، فقط این یک فرمان را روی **هر دو سرور** اجرا کنید؛ نصاب
نقش را تشخیص می‌دهد و تنظیم اتصال از پنل کامل می‌شود. فرمان نصب جداگانه برای رله
و اگزیت لازم نیست:

```bash
curl -fsSL https://raw.githubusercontent.com/Dark-Sky07/Simurgh-Tunnel/main/install.sh | sudo bash
```

پیش از تغییرات مهم، از تنظیمات فعلی بکاپ بگیرید:

```bash
sudo cp -a /etc/simurgh "/etc/simurgh.backup-$(date +%Y%m%d-%H%M%S)"
```

از `--force` یا حذف `/etc/simurgh` برای عیب‌یابی استفاده نکنید.

## ۳) پنل‌ها را امن باز کنید

اگر پنل فقط روی خود سرور قابل دسترسی است، دو SSH tunnel در دو ترمینال بسازید:

```bash
# ترمینال اول؛ پنل سرور خارج روی localhost:18787
ssh -L 18787:127.0.0.1:8787 root@EXIT_IP

# ترمینال دوم؛ پنل سرور ایران روی localhost:28787
ssh -L 28787:127.0.0.1:8787 root@IRAN_IP
```

سپس `http://127.0.0.1:18787` و `http://127.0.0.1:28787` را در مرورگر باز کنید.
این آدرس‌های localhost فقط برای دسترسی شما به پنل‌اند؛ در فیلد Public panel
address هنگام Pair نباید `127.0.0.1` بگذارید، چون سرور دیگر باید آن آدرس را ببیند.

## ۴) اتصال در حالت Direct — روش پیشنهادی برای شروع

### الف) آماده‌سازی روی سرور خارج

1. در Dashboard ببینید نقش سرور **exit** است.
2. در **Settings** حامل `tls` و پورت تونل، مثلاً `443`، را بررسی کنید. اگر چیزی را
   تغییر دادید، Save و سپس **Tools → Restart** بزنید.
3. اجازهٔ ورود رله به پورت تونل را بدهید. نمونه با UFW:

   ```bash
   sudo ufw allow from IRAN_IP to any port 443 proto tcp
   ```

   Security Group فایروال ابری را هم، اگر وجود دارد، جدا بررسی کنید.
4. سرویس مقصد باید روی خود خارج سالم باشد. برای نمونهٔ `8443`:

   ```bash
   sudo ss -lntp | grep ':8443 '
   curl -v --connect-timeout 5 http://127.0.0.1:8443/
   ```

   اگر سرویس شما HTTPS است، همان scheme و مسیر مناسب خودش را بگیرید. اگر تست
   loopback روی خارج جواب نمی‌دهد، اول سرویس مقصد را تعمیر کنید؛ تونل نمی‌تواند
   سرویس خاموش را بالا بیاورد.

### ب) ساخت لینک اتصال روی خارج

1. در پنل خارج به **Pair → Create a setup link** بروید.
2. در **Public panel address** مقدار `EXIT_IP:8787` یا دامنه و پورت واقعی پنل را
   وارد کنید.
3. لینک `simurgh://…` را بسازید و از کانال خصوصی کپی کنید. این لینک شامل
   اطلاعات ورود پنل است؛ آن را در چت عمومی، لاگ یا اسکرین‌شات نفرستید.

رله باید هنگام Pair بتواند به پنل خارج دسترسی داشته باشد. اگر پنل روی فایروال بسته
است، فقط برای مرحلهٔ Pair و فقط برای IP رله دسترسی موقت بدهید:

```bash
sudo ufw allow from IRAN_IP to any port 8787 proto tcp
```

### ج) واردکردن لینک روی ایران

1. در پنل ایران به **Pair** بروید.
2. لینک را در **Setup link** بچسبانید و **Pair** را بزنید.
3. پیام موفقیت یعنی توکن، آدرس، listenerها و fingerprint گواهی از خارج خوانده و
   ذخیره شده‌اند. نیازی به کپی دستی توکن نیست.
4. در Dashboard وضعیت باید به **up** برسد و RTT نمایش داده شود. تونل بلافاصله
   dialling را شروع می‌کند.

### د) ساخت فوروارد روی ایران

در **Ports** روی ایران:

- **Listen port:** پورت عمومی برای کاربران، مثلاً `8443`.
- **Target port:** پورت سرویس روی خارج، مثلاً `8443`.
- **Protocol:** مطابق سرویس، TCP یا UDP.
- **Name:** نامی خوانا مثل `3x-ui` یا `HTTPS`.

مقصد پیش‌فرض `127.0.0.1` است و از **سمت خارج** ارزیابی می‌شود؛ یعنی ترافیک پس از
عبور از تونل به سرویس loopback روی خارج می‌رسد. پورت کاربر را برای کاربران باز
کنید:

```bash
sudo ufw allow 8443/tcp
# اگر مپینگ UDP دارید، قانون جداگانهٔ UDP هم لازم است:
sudo ufw allow 5353/udp
```

## ۵) تست واقعی؛ بدون وابستگی به پنل VPN

این تست با یک پاسخ موقت ثابت، مسیر کامل کاربر ← ایران ← تونل ← خارج را ثابت
می‌کند و به تنظیمات 3x-ui وابسته نیست.

### الف) پاسخ آزمایشی را روی خارج اجرا کنید

اگر پورت `18080` آزاد است، این فرمان را در یک ترمینال روی خارج اجرا کنید و
ترمینال را باز نگه دارید:

```bash
python3 - <<'PY'
from http.server import BaseHTTPRequestHandler, HTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        body = b"simurgh-tunnel-ok\n"
        self.send_response(200)
        self.send_header("Content-Type", "text/plain")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *args):
        pass

HTTPServer(("127.0.0.1", 18080), Handler).serve_forever()
PY
```

### ب) پورت آزمایشی را از پنل ایران اضافه کنید

در **Ports** مپینگ TCP با Listen `18080` و Target `18080` بسازید و روی ایران
فایروال را باز کنید:

```bash
sudo ufw allow 18080/tcp
```

### ج) از یک دستگاه بیرون از سرورها تست بگیرید

از لپ‌تاپ یا یک سرور سوم، نه فقط از loopback خود رله:

```bash
curl -v --connect-timeout 10 http://IRAN_IP:18080/
```

پاسخ مورد انتظار:

```text
simurgh-tunnel-ok
```

این پاسخ یعنی listener ایران، مسیر تونل و تحویل به loopback خارج هر سه درست
کار کرده‌اند. `nc -vz IRAN_IP 18080` فقط بازبودن TCP را می‌بیند و جای این تست را
نمی‌گیرد.

پس از تست:

1. در خارج با `Ctrl+C` سرور آزمایشی را متوقف کنید.
2. مپینگ `18080` را از Ports حذف کنید.
3. قانون موقت را حذف کنید: `sudo ufw delete allow 18080/tcp`.
4. اگر دسترسی موقت پنل برای Pair باز کرده بودید، آن را هم محدود کنید:

   ```bash
   sudo ufw delete allow from IRAN_IP to any port 8787 proto tcp
   ```

## ۶) تست سرویس اصلی، سرعت و UDP

1. مپینگ آزمایشی را حذف کرده‌اید؛ حالا سرویس واقعی را از بیرون با همان پروتکل
   خودش تست کنید. مثلاً برای سرویس HTTP روی `8443`:

   ```bash
   curl -v --connect-timeout 10 http://IRAN_IP:8443/
   ```

2. شمارنده‌های **Dashboard / Ports** را پیش و بعد از تست ببینید؛ عبور ترافیک باید
   مقدار Moved و نمودار را تغییر دهد.
3. روی **رله** تست کوتاه و کنترل‌شده بگیرید:

   ```bash
   simurgh speedtest --seconds 6 --streams 1
   ```

   بعداً می‌توانید `--streams 2` را جدا مقایسه کنید. تست سنگین را در ساعت شلوغ
   اجرا نکنید؛ نتیجه به مسیر واقعی ISP، ساعت و محدودیت هر دو سرور بستگی دارد.
4. برای سنجش افت و jitter دیتاگرام از پنل **Speed test → UDP loss probe** یا روی
   رله از این فرمان استفاده کنید:

   ```bash
   simurgh speedtest --seconds 6 --streams 1 --udp
   ```

   `nc -u -vz` به‌تنهایی اثبات عبور UDP نیست. برای مپینگ UDP باید سرویس واقعی UDP
   و قوانین فایروال UDP را هم بررسی کنید؛ مثلاً DNS را با یک پرس‌وجوی واقعی.
5. وضعیت و عیب‌یابی تکمیلی:

   ```bash
   simurgh status --detail
   simurgh doctor
   simurgh logs -f
   ```

## ۷) حالت Reverse — وقتی خارج باید به ایران وصل شود

در Reverse جهت شروع اتصال برعکس است، ولی **فوروارد پورت کاربران همچنان روی رله
ایران است**. پورت listener تونل (`9443` در مثال) را با پورت کاربر (`8443`) یکسان
انتخاب نکنید:

```text
کاربر ──► رله ایران:8443
                ▲
                └── اگزیت خارج به listener شمارهٔ 9443 رله وصل می‌شود
```

1. در **Settings رله ایران**، مقدار **Who dials the tunnel** را `exit` کنید؛
   حامل و پورت reverse listener مثل `9443` را مشخص و Save کنید و از Tools ری‌استارت بزنید.
2. پورت reverse listener را روی ایران فقط برای IP خارج باز کنید:

   ```bash
   sudo ufw allow from EXIT_IP to any port 9443 proto tcp
   ```

   اگر حامل UDP انتخاب شده باشد، قانون باید UDP باشد.
3. در **Pair رله ایران** لینک راه‌اندازی بسازید. Public panel address باید آدرس
   قابل‌دسترسی پنل ایران برای اگزیت باشد. دسترسی موقت پنل را در صورت نیاز فقط به
   IP خارج بدهید.
4. در **Pair اگزیت خارج**، بخش **Connect to a reverse relay** لینک را وارد و ذخیره
   کنید و از Tools ری‌استارت بزنید.
5. مپینگ پورت‌های کاربران را مثل قبل در **Ports رله** بسازید و تست‌های بخش ۵ و ۶
   را انجام دهید.

هم‌زمان Direct و Reverse را برای یک جفت سرور فعال نکنید. فقط یک طرف باید dialler
باشد؛ در Direct رله و در Reverse اگزیت.

## ۸) اگر تست جواب نداد

| نشانه | بررسی بعدی |
|---|---|
| Pair خطای دسترسی می‌دهد | Public panel address نباید localhost باشد؛ دسترسی IP سرور مقابل به پورت پنل و صحت لینک را بررسی کنید. |
| تونل down است | `last_error` و Logs را ببینید؛ پورت تونل، IP دیaller، توکن Pair و fingerprint گواهی را بررسی کنید. |
| تونل up است ولی سرویس جواب نمی‌دهد | سرویس مقصد را با curl از loopback خارج تست کنید؛ Target port و TCP/UDP را تطبیق دهید. |
| روی ایران listener نیست | `sudo ss -lntup | grep ':8443 '`؛ مپینگ Enabled و خطاهای bind را بررسی کنید. |
| listener هست ولی تست بیرونی timeout است | UFW، Security Group ابر و محدودیت ISP/پورت را بررسی کنید؛ تست loopback به‌تنهایی فایروال خارجی را اثبات نمی‌کند. |
| TCP کار می‌کند و UDP نه | نوع مپینگ، قانون UDP فایروال، سرویس UDP و عبور UDP در مسیر ISP را جدا بررسی کنید. |
| اتصال مکرر قطع می‌شود | لاگ و RTT/loss را در همان مسیر بسنجید؛ تغییر carrier یا split را یکی‌یکی و با baseline قابل‌برگشت آزمایش کنید. |

فیلترینگ و کیفیت مسیر در ایران بین ISP، استان و زمان متفاوت است. هیچ carrier یا
تنظیمی تضمین عمومی عبور ندارد؛ نتیجه را روی همان رله و اگزیت خودتان اندازه بگیرید.
